# Speed measurement method v2 · DataPulse 0.5

DataPulse measures real HTTP application payload to Cloudflare. It does not run Ookla's proprietary engine, use Ookla's server network, or claim Ookla certification or 99% accuracy. Different endpoints, routes, traffic load, and timing can produce different legitimate results.

## Measured quantities

- Download and upload: successful payload bytes × 8000 ÷ monotonic nanoseconds, in decimal Mbps. The duration includes the full phase, request overhead and in-flight request completion. Upload payload contributes only after HTTP success. A transfer failure rejects the whole result.
- Idle latency: median of ten completed zero-payload HTTPS requests after warming a separate probe connection. Jitter is mean absolute difference between successive HTTP request durations.
- Loaded latency: independent zero-payload HTTPS requests during each transfer phase, with median, successive jitter, range, number of completed samples, and failed-probe counts. These are HTTP round trips, not ICMP ping or raw network RTT.
- Live graph: observed payload deltas every approximately 250 ms divided by actual elapsed monotonic time. Upload deltas are bytes handed to the HTTP transport, not per-packet acknowledgements, so live rates remain provisional. Final rates use only completed requests.
- Packet loss, ISP identity, external IP and accuracy percentage are not invented. Packet loss is not measured by HTTP request failures. The edge code is shown only if returned in a warm-up HTTPS response header; it is not a claim that every later request reached that same edge.

## Transfer process

Four independent HTTP/1.1 streams are warmed with 64 KiB each (256 KiB total). Ten idle probes follow. Each throughput phase uses four streams, starts with 256 KiB chunks, and adjusts each next request toward approximately 750 ms using the preceding completed request. Chunks are bounded at 64 KiB and 8 MiB. The phase stops starting requests after twelve seconds or its budget, with a ten-second per-call timeout and a ninety-second whole-test timeout.

The consented quick/extended payload caps are 64/256 MiB. Three quarters go to download including warm-up; one quarter goes to upload. Atomic reservations prevent all four streams together exceeding the payload cap. HTTP/TLS/TCP/IP overhead and zero-byte probe headers are additional. A fast connection can hit the cap quickly; phases under five seconds are explicitly flagged as short, never labelled 99% accurate.

DNS and sockets bind to the network present at test start. Default-network changes reject the result. Compression, redirects and automatic connection retries are disabled. Download payload lengths are verified. Cancellation, leaving the screen, or backgrounding stops the test and prevents incomplete results being saved.

## Original evidence

Each completed result stores its ID, timestamp, endpoint, actual edge header if present, method version, stream count, exact successful bytes, monotonic phase durations, payload budget, all HTTP latency samples, observed throughput samples and probe failures. The result page can export this evidence as JSON through Android's document picker. Existing v0.4 results keep their original summaries and have no invented retrospective samples. Room migration preserves both daily history and older speed results.

This evidence is locally generated by the measurement process, not a signed attestation from the server. It supports recalculating the displayed throughput but does not establish a 99% agreement with physical line capacity.

## Comparison protocol

For a useful independent benchmark, use a stable device/network, disable other test traffic, record VPN state and endpoints, alternate DataPulse and Ookla tests (never simultaneously), repeat at least five pairs, and compare distributions rather than selecting the best run. Repeat at low and high bandwidth, under congestion, and in both directions. A controlled reference link or traffic shaper and known server capacity are needed to quantify measurement error. This preview has not established a universal 1% error bound.
